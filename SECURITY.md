# Security policy

This is a static public-health education prototype. The real security contact must be configured before public production launch.

Template contact: `security@example.org`

## Scope

- Static HTML, CSS and JavaScript in this repository.
- Public content JSON files under `content/`.
- GitHub Actions workflow configuration.
- Static deployment metadata such as `robots.txt`, `sitemap.xml` and security documents.

## How to report a vulnerability

Send a concise report to the configured security inbox once it has been replaced with a real project-controlled address. Include the affected URL or file, impact, reproduction steps and any safe proof of concept.

Do not send personal health information, sexual-health details or identity documents in vulnerability reports.

## Not allowed

- Testing against real users or third-party health services.
- Social engineering.
- Denial-of-service testing.
- Exfiltrating or attempting to access private accounts, private repositories or hosting-provider control panels.
- Adding tracking, analytics, forms or third-party scripts as part of a report.

## Expected response

For production use, the project owner should acknowledge valid reports, triage severity, prepare a fix, publish a short remediation note when appropriate and preserve evidence needed for incident review.

Until a real security inbox and responsible owner exist, this repository is not ready for public production launch.
